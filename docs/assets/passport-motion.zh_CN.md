# AI PassportOS 角色帧动画

按已确认的安静风格接入预渲染动画：待机时偶尔呼吸、眨眼，切换按钮时关注目标，
返回身份卡或头像可见时真实操作成功后轻点头。导航不等待动作完成，新选择会覆盖旧动作。

## 选择动态角色

本次个人构建包含已确认的 18 帧角色。没有已保存静态头像时默认使用动态角色。
已有上传场景继续优先，升级后保留原选择。在身份卡页长按确定两秒打开隐藏菜单，
选择「Wi-Fi 配置」，连接屏幕显示的热点，在场景列表选择 **动态角色 · 眨眼与回应**、
**外滩看夜景 · 动态** 或 **撸猫 · 动态**。选择会把场景编号存入头像槽的头部扇区，重启后仍保留，
不改资料/NVS 和全屏图片槽。选择其他场景可恢复静态头像。

公共源码构建自带两场景展示：动态角色和外滩夜景，经作者同意公开。公共构建没有
静态画廊图片，也没有撸猫场景；个人素材包会在本机补上这些内容。

## 运行方式与布局

- `main/passport_animation.c` 是不分配内存、不依赖 LVGL 的纯 C 播放器，
  接受可回绕的 32 位单调毫秒时间，补帧工作量有明确上限。
- `main/passport_ui.c` 只在动态角色可见时运行 50 ms 定时器，通过换图切帧，
  不平移、缩放或整体改变透明度。临时头像可用 100 ms 眨眼；上传的静态场景不运行头像定时器。
- 选择变化直接更新现有按钮样式，保留头像对象；离页先停止播放器、删除定时器，再删 UI。
- 保留现有左侧 76×150 头像区域。AGENT 使用近处向下关注，QR 使用更明显的右下视线，
  不把左侧按钮误映射成朝屏幕左看。点头含恢复中性姿态共 440 ms。
- 左/右视线源帧仍保留在素材集中；保留左看帧不代表新增了鼠标或传感器跟随。
- 夜景使用 216×112 横向场景，撸猫使用 76×150 竖向区域，各自六帧安静循环。
  按钮立即响应，切换高亮不重启动画；原角色仍保留关注/点头交互。进入跑酷页先停头像定时器再删 UI。

## 素材与重建

源帧与 `animation-manifest.json` 放在 Git 忽略的 `assets/private/passport-motion/`。
来源为用户提供的默认像素角色，以及 2026-10-22 用内置 image_gen 生成并确认的动画条。
展示用源素材（仅默认角色和夜景）提交在 `assets/showcase/`，
`assets/images/passport_motion.c` 由它们生成：

```text
python tools/build_passport_motion.py --pack assets/showcase/motion --scene-pack assets/showcase/scenes --scene night --public --output <临时目录>
```

把该目录里的 `images/passport_motion.c` 和 `passport/motion-manifest.json` 复制进
`assets/`，再更新 `assets/passport/manifest.json` 里的校验值。

在已有个人字库/场景资源目录旁生成动画源码：

```text
python tools/build_passport_motion.py --pack assets/private/passport-motion --scene-pack assets/private/passport-scenes --output build/passport-assets
```

用于固件构建时，输出目录必须已经包含个人字库、字符串、头像与场景集；此工具不重新生成它们。
生成前检查帧数、RGBA/76×150、透明度、安全边缘和脚底基线，全部有效后才替换生成源码。
像素格式是小端 RGB565 颜色平面加 A8 平面。18 个帧描述符复用 14 组像素，
Flash 像素净载荷 478,800 字节（467.6 KiB），不分配整帧解码缓冲。
新增两场景去重后增加 412,920 字节像素：夜景五张 RGB565 图，撸猫五张 RGB565A8 图，
循环最后一帧复用首帧。三场景合计 891,720 字节像素，不进行运行时解码。

### 个人构建的防丢失检查（0.1.4）

合并版保留了播放器，但构建时未选择个人资源，因此编入公共空动画集（`passport_motion_count=0`）。
现在个人资源重新生成时会自动带入本地动画。忽略的 `private/passport-build.json` 内容为：

```json
{"asset_dir":"build/passport-assets","required_motion_scenes":3}
```

正常固件构建读取该配置，要求三场景齐全并核对生成源码哈希；缺失或不完整时明确失败，
不再静默生成个人静态版本。配置、动画清单和生成源码均为 CMake 配置依赖，增量构建也会重新检查。
需要公共构建时显式使用 `-DPASSPORT_USE_LOCAL_ASSETS=OFF`。新场景源帧保存在忽略的
`assets/private/passport-scenes/`，来源为用户确认的 2026-10-22 image_gen 夜景/撸猫样片。

主资源生成器支持 `--motion-pack`、`--scene-pack`，个人构建时自动发现本地素材，并在资源清单中记录动画源码。
个人 LVGL 预览可指定 `--require-motion-scenes 3`（再加 `--require-agent-name Nora` 检查个人智能体形象），
避免未带入资源时测试静默跳过此功能。公共展示版用 `--require-motion-scenes 2` 检查。

本次是编译内置动画，PAV1 静态图片仍兼容，不能上传此帧集或 GIF。
内置场景选择增加 16 字节头部变体：格式为 3，保留字节存场景编号、版本 1 和零，
CRC 覆盖前十二字节。固定编号为 1 默认角色、2 夜景、3 撸猫。
旧固件会忽略该变体并回退，新固件仍可读取已有静态图片；未启用 I8 解码。

## 验证与真机验收

时序测试覆盖呼吸/眨眼、帧边界、最新输入抢占、隐藏、长时间停顿和计时回绕。
素材测试覆盖可复现性、错误/空白/缺失/裁切帧、基线漂移及个人输出保护。
实际 LVGL 测试分别运行公共和个人资源，在 32 KB LVGL 池内验证 100 次高亮切换、
切帧、定时器清理、静态头像回退、点头抓帧、600 次页面切换（含合并的跑酷页）、字形覆盖与独立二维码精确解码。
另覆盖场景选择头 CRC、重启/缓存重建、上传期间互斥、图片槽保留和构建防丢失检查。

0.1.4 验证完成后，将实际构建身份、门禁结果、固件/ELF 哈希记录到忽略的 `build/scenes-handoff.json`；
原 `motion-handoff.json` 保留较早的 0.1.3 结果。
主机预览和构建成功不能证明真实时序、功耗、SPI 带宽、Wi-Fi 并发或设备显示效果；
这些需要真机验证，并检查切换静态场景后能再启用动态角色。刷写需针对具体候选版本获批并核对设备分区兼容性。

### 2026-10-22 真机检查点（0.1.3）

用户批准后，实读 COM7 分区表与已验证候选一致。仅向 `0x10000` 写入 6,414,080 字节应用，
写入哈希校验通过，未写 NVS、PHY 或媒体分区。受控重启后的 35 秒日志匹配归档 ELF，
只出现一次启动，未发现崩溃/看门狗特征，USB 只读资料查询成功。随后已关闭串口。
随后用户确认：待机眨眼、上/下选择关注、从菜单返回点头三项均正常。
这三项动画行为的真机验收为 PASS；Wi-Fi 峰值内存实测、长时间稳定性及功耗/唤醒测试仍未完成。


### 2026-10-22 场景固件启动检查点（0.1.4）

用户批准了应用 SHA-256 以 `5308afc88ec66465` 开头的归档候选版本。
本次实读 COM7 分区表与归档一致，仅向 `0x10000` 写入 6,833,808 字节应用，
esptool 写入哈希校验通过。扇区擦除止于 `0x695000` 之前，保留 NVS、PHY
和始于 `0x780000` 的媒体分区。应用 Flash 余量为 964,976 字节（942.4 KiB，12.4%）。

受控重启后的 35 秒观察匹配 ELF 标记 `3ee87a1b`，只出现一次启动，
未发现崩溃/看门狗特征，USB 只读资料查询成功。启动空闲堆为 120,976 字节，
最大连续空闲块为 106,496 字节；此值并非 Wi-Fi 峰值内存实测。随后已关闭串口。
随后用户确认三种动画、所选场景重启保留、跑酷进入/返回均正常，这些行为真机验收为 PASS。
Wi-Fi 峰值内存、长期稳定性和功耗/唤醒仍未验证。本次验收另报告文字滚动及 NFC 设置问题，
在 0.1.5 后续修复中处理。
