# AI PassportOS v0.1 设计

日期：2026-10-20。状态：用户已于 2026-10-20 批准设计，尚未开始应用实现。另见[实施计划](passport-os-v0.1-plan.zh_CN.md)。

## 目的与范围

制作可佩戴的多功能身份工牌，开机进入身份卡，离线仍有使用价值。交付身份卡、Profile、个人主页二维码、本地资料持久化和小帧动态头像。用户已暂缓小智语音与 MCP 集成，后续改接 Muse。

语音笔记需求仍保留，但须先替换原先依赖的小智识别链路，才能实现并验收。Muse、语音识别、手机 BLE 改资料和实验室遥控不属于本轮实现。本轮不能被称为原始完整语音版 v0.1。

姓名、职位、单位/标签、头像和主页必须来自用户。空字段有明确的未设置状态；缺少主页时，不生成虚构的个人二维码。

## 基础与方案选择

采用 `FoloToy/ai-passport`，固定提交 `3d685a90bdb96dd8526d84edde1e63fec25b460e`：ESP-IDF 5.5.3、ESP32-C3、8 MB Flash、无 PSRAM，以及现有 LVGL 9.5 依赖锁。保留 BSP、引脚定义和 USB Serial/JTAG 控制台，在 `feature/passport-os-v0.1` 分支工作。

推荐官方硬件基线，因为它已提供屏幕、按键和电量 API，允许实现独立应用。小智发行版保留了已经暂缓的语音依赖，且使用不同 SDK；重写驱动会增加硬件风险，无法改善本轮功能。在 `main` 实现新的应用页面，不沿用基线测试菜单及界面外壳。

## 页面与按键

使用 240×320 竖屏：深藏蓝背景、浅色文字、少量青绿色和白色二维码底板。重要内容距离左右边缘至少 22 像素，并避开圆角。渲染验证时可为可读性调整间距。

| 页面 | 内容 |
| --- | --- |
| 身份卡 | 顶部时间与电量；居中 64×64 头像；姓名、职位、换行显示的单位/标签；页码提示。 |
| Profile | 姓名、职位、单位/标签和介绍；长内容用按键滚动。 |
| 个人主页 | 高对比度二维码与目标主机名，或明确的未设置状态。 |
| 菜单 | 显示亮度、关于、返回；不展示尚未接入的语音入口。 |
| 亮度 / 关于 | 30%、60%、90% 三档亮度并持久化，默认 60%；应用版本与构建信息，不显示身份秘密。 |

| 输入 | 身份卡 / Profile / 个人主页 | 菜单与子页面 |
| --- | --- | --- |
| UP / DOWN 短按 | 上一页 / 下一页；长 Profile 先滚动，到边界后再翻页。 | 移动选项；在亮度页调整亮度。 |
| OK 短按 | 打开菜单，记住来源页。 | 选择选项；关于页回菜单；返回项回来源页。 |
| OK 长按 2 秒 | 返回身份卡。 | 返回身份卡。 |
| UP / DOWN 长按 | 本轮不分配额外动作。 | 本轮不分配额外动作。 |

一次长按只产生一次动作，松手时抑制短按。双击导航效果等于两次短按，不能产生额外动作。按键回调只做有界入队，不访问 LVGL 与 NVS。

本次开机尚未明确校时时，显示 `--:--`；校时后按 Asia/Shanghai（UTC+08:00）显示，电脑工具可通过 USB 校时。离线显示不等于彻底断电后仍能保持准确时间。电量读取失败时显示 `--`，不阻止身份卡显示。

## 资料、字体、头像与二维码

在独立的 `passport` NVS 命名空间保存带版本号的完整资料和显示设置。整体校验后才提交；导入被拒或存储失败时保留上次有效记录。不能为了处理应用数据错误而擦除其他命名空间或整个 NVS 分区。

首次编辑使用被 Git 忽略的本地 UTF-8 JSON 与 USB 配置工具。字段上限（不含末尾 NUL）：`name` 64 字节、`title` 96、`research` 192、`bio` 512、`homepage` 128。拒绝无效 UTF-8、超长字段、不支持的控制字符和非空但格式错误的 URL。主页必须使用 `https` 或 `http`，并有主机名。工具不能上传资料或在日志中显示凭据。

复用 USB 控制台，用逐行 JSON、有界请求、请求编号和独立响应前缀通信。支持读取资料、校验后替换资料和设置当前时间。电脑端显式选择目标串口，不探测无关蓝牙串口；普通日志不能被误认成协议响应。

从固定文案与配置资料生成可重建的字体子集。导入变化后的文字前，工具核对固件公布的字形清单；缺字时明确报错并保留资料，增加字符需重建字体子集。私人 JSON 与个人生成字形清单均保持 Git 忽略。个人资料缺失时，未设置状态允许先构建开发版。

头像预处理为三帧 64×64 RGB565，像素数据总计不超过 24,576 字节，存入 Flash。用户提供素材前，使用明确的临时中性头像。定时器切换少量眨眼帧；不加入 GIF 解码器或整屏帧缓冲。

从有效 URL 生成真实二维码：黑码白底、四模块静区、整数像素缩放。在 196×196 可用区域内，含静区后仍保证每模块至少三像素。生成或容纳失败时显示明确错误，不能使用装饰矩阵或其他 URL。主机验证公开测试 URL，真机验证最终个人 URL。

## 架构与故障处理

分离纯输入/资料模型、NVS 适配、USB 处理、LVGL 显示与编译资产。单一应用所有者串行处理状态；工作任务处理有界的存储/USB 操作。LVGL 操作位于其任务中，或持有 `bsp_lvgl_lock()`。删除页面前先停止相关定时器和事件生产者。

保留现有小型显示缓冲，初始沿用基线 LVGL 内存池。调整分配前测量总堆、最大连续空闲块和渲染表现。本轮不启动无线/音频协议栈。头像帧放 Flash，只激活当前帧描述符。

应用数据缺失或损坏时显示未设置字段，并准确记录诊断。存储失败不能报告成功。异常 USB 请求不能引起崩溃或改变状态。动画期间保持导航与 USB 更新响应。

## 验证与交付

1. 准备项目要求的五个技能和准确的 ESP-IDF 5.5.3 环境；应用修改前保留未改动基线的构建结果。使用 Windows 原生工具，不擅自迁移 WSL 或修改全局配置。
2. 针对输入/页面、UTF-8/URL 校验、资料替换、异常/超大 USB 请求、缺字、存储失败和二维码生成，运行主机验证。
3. 执行仓库静态与固件验证，保留提交、日志、二进制、匹配符号和 SHA-256。合并镜像生成不等于获得刷写许可。
4. 写入前识别实际目标、现有/拟用分区、准确产物及已存数据影响，并取得此次授权。在所选布局允许时保留配置，明确说明不兼容变化。不做未授权整片擦除。原固件读回备份可选，不作为强制前提。
5. 真机验证冷启动身份卡、断网显示、重启保留资料、按键、中文字形、手机扫码、亮度持久化、动画响应和缺失资料处理。

分别报告 Build、Host tests、Device tests 与 Unverified。占位资料构建属于开发版；个人二维码/头像验收须等待实际资料与真机检查。

## 已观察到的起点

官方源码已下载；交接包没有之前的定制源码/补丁。当前 Windows x64 shell 有 Python 3.14.6 与 Git；PATH 及少量已检查的常见 ESP-IDF 目录中未找到 ESP-IDF、CMake、Ninja 与主机 C 编译器，其他位置可能有安装。

用户确认 USB 数据线连接、设备已开机且界面正常。初次枚举只有蓝牙 COM3/4/5/6；之后复查识别到 COM7 上的 Espressif USB Serial/JTAG，VID 303A / PID 1001，驱动已启动。尚未查询实际目标芯片、现有固件和 Flash 布局。本设计尚未执行基线构建、应用主机测试、刷写或真机验收。
