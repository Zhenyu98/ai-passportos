# 设置保存修复

手机连接 Badge 热点后，资料中的任一字符不在编译的小字库中，就会在写入
NVS 前被拒绝；页面直接显示内部错误码 `unsupported`。旧字库只覆盖初始
资料，因此正常修改中文姓名也可能失败。

默认字体现包含 GB2312 的 6,763 个汉字、常见标点、ASCII 和界面文字，
公共构建共 6,881 个字形；个人构建仍可补充其他字符。20 像素字体的位图
超过小格式的 1 MB 索引范围，两个字号都启用 LVGL 大字体索引格式。字形
保存在 Flash，渲染内存池保持 32 KB。未覆盖的生僻字会指出字段、字符和
Unicode 码点，不再只显示错误码。

配置保存链路拆分为可复用模块：

- `passport_json`：有界 UTF-8 JSON 解析、重复字段检查和数值范围校验。
- `passport_settings`：资料部分更新与可读错误提示。
- `passport_profile_check`：统一校验并指出具体缺失字形。
- `passport_app`：USB 与 Wi-Fi 共用请求存储、确认机制和单写者工作任务。

热点保存自己的回调结构，不再引用调用者栈上的临时变量。先保存资料，再
校时；校时失败不会把已经成功保存的资料误报为失败。HTTP 读取限制重试
次数。超时请求在工作任务确认前保留其位置，防止另一连接误收旧操作结果。

USB 的 `info` 增加 `glyphs_complete`。不超过 400 个字形的字库仍返回完整清单，
更大的字库返回空清单与 `false`，保证回复不超过 4 KB 的消息上限（原为 8 KB，
为 Muse 固件腾出内部内存而缩小）。配套主机工具此时由设备执行
字形校验；扩展字库固件应使用同步更新的主机工具。

回归检查包含常见中文姓名、异常和部分更新、具体缺字、大字库 USB 响应，
以及跨连接超时请求。真实 LVGL 逐一检查两个字号的字形，并通过当前全屏
图片页渲染二维码测试图，拒绝读取旧截图冒充本次结果。头像元数据改为
统计三帧总量，修正此前只统计一帧的数字。

固件验证与手机真机验收分开记录。只有获准的具体固件才能刷入；分区兼容
时通过分段烧录保留 NVS 和媒体，不以擦除设备作为 `unsupported` 的修复手段。

## 媒体回读修复（0.1.2）

存储媒体的读取端使用了错误的 CRC 初值，导致写入媒体分区的每个头像场景
和全屏图片都无法通过校验，并被静默回退为内置默认图：选择场景后徽章没有
变化，图片页一直显示"未上传图片"。读取端现在与写入端使用相同的 zlib
兼容初值。新增的主机媒体测试核对精确 CRC 向量、故意非对齐的分块流式
写入、回读，以及损坏数据的拒绝。

同时包含两项配套修复：`已保存` 等状态标题在三秒后自动消失，不再常驻；
缓存像素改为下次加载时延迟释放，渲染帧不会读到已释放或解除映射的内存；
互斥量创建失败时存储直接拒绝操作。热点占用堆内存时，头像会回退为 Flash
映射而不是消失。
